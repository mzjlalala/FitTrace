# 健身网站开发路线图（Roadmap）

> **目标：** 面向所有健身人群的一站式健身网站——提供训练计划、动作教程、饮食建议、训练记录、数据分析与知识库，降低入门门槛，成为用户的「健身教练 + 记录工具」。
>
> **架构：** 前后端分离单体（Spring Boot 3 + Vue 3），PostgreSQL + Redis。AI 助手后期以独立 Python 服务（**LangChain + LangGraph**）接入，Java 后端通过 Spring AI MCP Server 开放 MCP 能力，AI 服务作为 MCP Client 调用数据与工具。
>
> **技术栈：** Java 21 (LTS) · Spring Boot 3.x · MyBatis-Plus · PostgreSQL 16 (+ pgvector) · Redis · Spring Security + JWT · Vue 3 + TypeScript + Vite + Pinia + Element Plus + ECharts

---

## 1. 关键决策：Java 版本选择（为 MCP 预留）

**推荐：JDK 21（LTS）+ Spring Boot 3.x（当前最新稳定版）+ Maven**

选择理由：

1. **Spring Boot 3.x 要求 Java ≥ 17**，Java 21 是企业主流 LTS，官方支持到 2031 年 9 月；Spring、MyBatis-Plus、Lombok 等生态对 Java 21 支持成熟稳定。
2. **MCP 完全兼容**：官方 `mcp-java-sdk`（io.modelcontextprotocol.sdk）与 Spring AI 的 `spring-ai-starter-mcp-server` 均支持 Java 17+，在 Java 21 上运行成熟，可把「查询动作 / 查询计划 / 写入训练记录」等能力直接暴露为 MCP Tools（HTTP / SSE 传输）。
3. Java 25 虽已是新 LTS，但生态迁移尚未完全收敛，本项目无必要冒进；Java 21 → 未来升级路径平滑。

> 补充：如果团队强依赖国内组件兼容性，JDK 17 也可行，但与 Spring AI MCP 的长期演进相比，**优先选 21**。

## 2. 系统架构

```
┌────────────────────────────────────┐
│  Vue 3 前端（Vite + TS）             │   Nginx 托管静态资源
│  Element Plus / Pinia / ECharts     │
└────────────────┬───────────────────┘
                 │  REST (JSON) / JWT
┌────────────────▼───────────────────┐
│   Spring Boot 3 后端（单体）          │
│   Spring Web MVC · Spring Security  │
│   MyBatis-Plus · Redis 缓存          │
│   ┌───────────────┐  ┌────────────┐  │
│   │ PostgreSQL 16 │  │   Redis    │  │
│   │  (+ pgvector) │  └────────────┘  │
│   └───────────────┘                  │
└───────────────┬─────────────────────┘
                │  MCP Server（Spring AI，后期开放）
┌───────────────▼─────────────────────┐
│  AI 助手（独立 Python 服务）           │  LangChain + LangGraph
│  FastAPI · LangChain · LangGraph    │  MCP Client 调用后端
│  自有模型 / RAG (pgvector)           │
└─────────────────────────────────────┘
```

- **前后端分离**：Vue 3 SPA + Spring Boot 纯 REST API，JWT 无状态鉴权。
- **单体起步**：MVP 阶段不分微服务，按 package 划分业务模块，后续按需拆分。
- **后期 MCP**：后端内置 `mcp` 模块（Spring AI MCP Server），对外暴露业务 Tools。

## 3. MVP 范围界定

MVP 聚焦核心闭环：**注册登录 → 看动作教程 → 选训练计划 → 记录训练 → 查看基础数据**。

| 模块 | MVP（第一版） | V2 | V3（含 AI） |
|---|---|---|---|
| 用户体系 | ✅ 注册 / 登录 / 个人信息 | 角色、管理后台 | 第三方登录 |
| 动作库 | ✅ 分类 + 动作详情教程 | 视频课程、搜索 | 动作纠错（AI） |
| 训练计划 | ✅ 内置模板 + 按目标推荐 | 自定义计划、周期化 | 智能生成计划（AI） |
| 训练记录 | ✅ 记录 / 历史 / 编辑删除 | 图表分析（重量·容量趋势） | AI 解读 |
| 数据分析 | ✅ 基础统计（打卡、热力图、PR） | 进阶图表 | AI 训练建议 |
| 饮食管理 | ✅ 饮食记录 + 每日营养汇总 | 饮食计划、食物库管理 | AI 饮食计划 |
| 知识库 | — | 文章 | 视频、百科 |
| AI 助手 | — | — | ✅ LangChain + LangGraph 服务 + MCP |

## 5. 数据库设计概览（MVP 部分）

PostgreSQL 16，UTF-8，核心表：

> **半结构化数据用 jsonb**（如动作的 steps/tips、AI 生成内容）；**V3 阶段启用 pgvector 扩展**做知识库语义检索（RAG），直接复用主库，无需额外引入向量数据库。

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `sys_user` | 用户 | id, username, password, nickname, avatar, phone, status |
| `user_profile` | 身体数据与目标 | user_id, gender, birth_date, height_cm, weight_kg, goal, fitness_level, weekly_frequency |
| `action_category` | 动作分类 | id, name, code, sort, parent_id |
| `action` | 动作 | id, category_id, name, muscle_group, difficulty, equipment, cover_image, video_url, description, steps, tips, cautions, status |
| `plan` | 计划模板 | id, name, goal, level, duration_weeks, frequency_per_week, description, cover_image, status |
| `plan_week` | 计划周 | id, plan_id, week_no |
| `plan_day` | 计划日 | id, plan_week_id, day_no, rest_flag, title |
| `plan_day_action` | 当日动作编排 | id, plan_day_id, action_id, sort, sets, reps, weight_mode, rest_seconds |
| `training_record` | 训练记录 | id, user_id, plan_id, plan_day_id, training_date, duration_minutes, feel, note |
| `training_record_set` | 训练组数据 | id, record_id, action_id, set_no, weight_kg, reps, done_flag |
| `user_plan` | 用户订阅的计划 | id, user_id, plan_id, start_date, status |
| `diet_food` | 食物库 | id, name, category, calories_per_100g, protein_per_100g, fat_per_100g, carb_per_100g, status |
| `diet_record` | 饮食记录 | id, user_id, record_date, meal_type, food_id, quantity_g |

> V2 新增：`kb_article`、饮食计划等。食物营养以每 100g 为基准存储，记录按食用克数等比换算。

## 6. API 接口规划（REST，统一前缀 `/api`）

| 分组 | 接口 | 方法 |
|---|---|---|
| 认证 | `/api/auth/register` `/api/auth/login` `/api/auth/logout` | POST |
| 用户 | `/api/user/profile` | GET / PUT |
| 动作 | `/api/actions`（分页/筛选）`/api/actions/{id}` `/api/actions/categories` | GET |
| 计划 | `/api/plans` `/api/plans/recommend` `/api/plans/{id}`（含周/日/动作） | GET |
| 计划订阅 | `/api/user-plans` 开始 / 结束 / 我的计划 | POST / PUT / GET |
| 训练记录 | `/api/training-records`（CRUD）`/api/training-records/{id}` | POST / GET / PUT / DELETE |
| 统计 | `/api/training/stats/heatmap` `/api/training/stats/summary` | GET |
| 饮食 | `/api/diet/foods`（食物库）`/api/diet/records`（记录 CRUD）`/api/diet/records/summary`（营养汇总） | GET / POST / PUT / DELETE |

> 统一返回体 `{ code, message, data }`，JWT 放 `Authorization: Bearer <token>`。

## 9. MCP / AI 预留方案（V3，提前确定技术路线）

1. **Java 后端开放 MCP**：新增 `mcp` 模块，引入 `spring-ai-starter-mcp-server`，把「查询动作 / 查询计划 / 查询训练记录 / 创建训练记录」等封装为 MCP Tools，走 HTTP / SSE 传输。
2. **Python AI 服务（LangChain + LangGraph）**：独立 Python 服务（另建仓库），基于 **LangChain + LangGraph** 构建：LangChain 提供 LLM 抽象、RAG 组件，LangGraph 编排多步对话 / 工作流（FastAPI 托管服务 API）；通过 `langchain-mcp-adapters` 以 **MCP Client** 调用 Java 后端暴露的 Tools；向量检索复用主库 PostgreSQL 的 pgvector 扩展，对外提供对话式教练。
3. **外部接入**：后端 MCP endpoint 同时可供 Claude / IDE 等外部 MCP Client 直连。
4. 结论：**Java 21 + Spring Boot 3.x 天然满足该路线**，无需为 MCP 预留额外技术债务。

## 11. 风险与注意事项

1. **动作/计划内容**：动作教程、计划编排属于领域内容，需提前整理数据结构（建议团队先出内容清单）。
2. **推荐逻辑 MVP 从简**：第一版按「目标 + 健身水平 + 训练频率」规则匹配即可，不引入复杂算法。
3. **数据统计口径**：PR（个人纪录）、训练量等指标定义需在 P4 前统一。
4. **饮食与知识库**：内容型模块工作量集中在内容生产，工程上较简单，放 V2 合理。
5. **安全**：密码 bcrypt 加密、JWT 过期与刷新策略在 P1 落地。
6. **部署**：Docker Compose（PostgreSQL + Redis + 后端 + Nginx）作为标准交付方式，MVP 阶段即可用。
